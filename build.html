Build

C++20. From the library directory:

cmake -S . -B build
cmake --build build

The library target is eph. No data files are required. An optional directory of .bsp kernels can be passed to the Ephemeris constructor.

Pluto and the asteroids default to a one-year series (EPH_MINOR_SERIES=year). The 16-day series is the same build with -DEPH_MINOR_SERIES=full. The year series is the one in the npm package. What that changes in the arcsecond bounds is on the Accuracy page.

The comparison suite is a separate project, Empheresis Comparator. It downloads Swiss Ephemeris when it is built. The library project does not.

eph_example_tests is the library's own check of the examples. It is built only when this directory is the CMake top level, with a normal C++ compiler.

JavaScript package

Install the published package:

npm install wizards-ephemeris

Node 20 or newer. The call shape is on the JavaScript page. A source build still writes a tarball, js/pack/wizards-ephemeris-0.2.0.tgz, if you want to try a change before it is published. Node loads eph.wasm from the same directory as the package entry. In a bundler, pass that file's URL to Ephemeris.load({ wasmUrl }).

The toolchain is stock Emscripten 6.0.11, not the p2996 compiler, and Node 20 or newer. The plain C++ build above does not produce the wasm.

Linux

Install and activate the SDK once per shell:

git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install 6.0.11
./emsdk activate 6.0.11
source ./emsdk_env.sh

From the library directory:

./scripts/build-js.sh

The script uses the year series. For the 16-day series:

EPH_MINOR_SERIES=full ./scripts/build-js.sh

That configures build-js, builds the eph_js target, runs the Node tests, and writes js/pack/wizards-ephemeris-0.2.0.tgz. The archive contains dist/eph.js, dist/eph.wasm, and the TypeScript entry.

Docker

From the library directory:

docker build -f Dockerfile -o js/pack .

The first stage uses emscripten/emsdk:6.0.11 and compiles only the wasm. The second stage uses node:20, runs the Node tests, and packs the same tarball into js/pack. The image does not publish the package.

npm run test:browser, from js/, is the Chromium check. It stays on the host and needs js/dist from either build.
